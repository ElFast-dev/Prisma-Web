OPFS-WL AutoTest V1

Dos Dedicated Workers · Dos conexiones SQLite independientes · OPFS · Web Locks

Esta prueba es distinta de Concurrency AutoTest. Aquí cada cliente abre su propia conexión SQLite al mismo archivo OPFS. No hay SharedWorker ni propietario único. SQLite y OPFS-WL deben coordinar los bloqueos entre los dos Workers.

Se utiliza una base sintética exclusiva para esta ejecución. Si alguna comprobación falla, la carpeta se conserva para investigar. La limpieza automática solo se realiza después de verificar las escrituras y la reapertura desde ambos Workers.

Memoria y alcance. La página intenta medir la memoria del navegador solo si la API está disponible. El dato, si aparece, es una estimación del navegador, no una medición completa de la RAM física de 4 GB del teléfono. SQLite OPFS-WL usa Web Locks y requiere Atomics.waitAsync. Las transacciones deben ser breves y la aplicación debe tolerar SQLITE_BUSY. Esta herramienta no toca SAH pool, Recovery AutoTest, V4, V8 ni datos de Prisma.
