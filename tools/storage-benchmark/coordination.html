SharedWorker coordinador + SQLite SAH pool · V8

V8: prueba dos pestañas con un solo propietario SQLite y traspaso mediante instantánea binaria verificada.

Solo datos sintéticos. Cada pestaña crea un Dedicated Worker; el SharedWorker elige uno como propietario de la base y reenvía todas las operaciones a ese único Worker. Los demás quedan en espera. No usa datos personales ni modifica Prisma. El registro de actividad y los IDs de Worker se reinician al recargar; eso es normal. V8 exporta el archivo SQLite antes del relevo y lo importa en el nuevo propietario; el total debe conservarse. Abre esta dirección en dos pestañas normales del mismo Brave.

Esperando conexión.

«Preparando propiedad» significa que la pestaña fue elegida, pero SQLite aún no está listo. Solo «Propietaria activa» habilita las operaciones. Para transferir el acceso, pulsa «Ceder propiedad» antes de cerrar la pestaña propietaria.

Escrituras desde ambas pestañas

Cuando las dos estén conectadas, pulsa una vez «Insertar 25» desde cada pestaña. El SharedWorker enviará ambas operaciones al mismo Dedicated Worker.

Después del relevo, la nueva propietaria debe insertar otra tanda y pasar de 50 a 75; reabre SQLite y confirma 75. Luego consulta desde la pestaña anterior e inserta allí otra tanda: debe llegar a 100, porque la operación se reenvía al propietario activo. El botón permite tandas adicionales; pulsa solo las indicadas en el procedimiento.

Pendiente.

Esperado: dos pestañas con el mismo ID de SharedWorker, un único propietario Dedicated Worker y el mismo total de filas antes y después del relevo. La transferencia se rechaza si el nuevo Worker no encuentra el archivo SQLite anterior o recupera menos filas de las confirmadas por el propietario saliente.
